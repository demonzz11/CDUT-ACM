# 硬币组合问题解决方案

## 问题描述

给定4种硬币的面值 `c₁, c₂, c₃, c₄`，进行 `n` 次查询。每次查询给出每种硬币的数量限制 `d₁, d₂, d₃, d₄` 和目标金额 `s`，求使用不超过给定数量的硬币组成金额 `s` 的方案数。

## 算法思路

### 核心思想

1. **完全背包预处理**：首先计算无数量限制时的方案数
2. **容斥原理处理限制**：对于每种硬币的数量限制，使用容斥原理计算合法方案数
3. **正难则反**：先计算所有方案，再减去超出限制的方案

### 详细步骤

#### 1. 完全背包计算无限制方案数

- 定义 `f[s]` 表示用给定面值的硬币组成金额 `s` 的方案数（无数量限制）
- 使用完全背包DP计算：`f[j] += f[j - c[i]]`
- 时间复杂度：O(4 × MAX_S)

#### 2. 容斥原理处理数量限制

对于每种硬币 `i`，限制为最多使用 `dᵢ` 枚。

**关键观察**：

- 如果不考虑限制，总方案数为 `f[s]`
- 对于硬币 `i`，不合法的情况是使用了至少 `dᵢ + 1` 枚
- 如果先拿出 `dᵢ + 1` 枚硬币 `i`，那么剩下的硬币无论怎么选，使用硬币 `i` 的数量都至少为 `dᵢ + 1`
- 因此，硬币 `i` 不合法的情况数为 `f[s - (dᵢ + 1) × cᵢ]`（如果 `s - (dᵢ + 1) × cᵢ ≥ 0`）

#### 3. 多硬币的容斥原理

当有多个硬币都超出限制时，直接减去各个硬币的不合法方案会重复计算。

**解决方案**：

- 使用二进制枚举所有硬币的组合（共 16 种情况）
- 对于每种组合：
  - 计算需要拿出的硬币总价值：`res = Σ (dⱼ + 1) × cⱼ`（对于组合中的硬币）
  - 剩余金额为 `s - res`
  - 如果 `s - res ≥ 0`，剩余金额的合法方案数为 `f[s - res]`
- 根据容斥原理：
  - 组合大小为奇数：减去 `f[s - res]`
  - 组合大小为偶数：加上 `f[s - res]`

## 代码实现

```cpp
include <bits/stdc++.h> 
using i64 = long long;
i64 f[100005], c[4], d[4];
void go() {
 for (int i = 0; i < 4; i++)
 std::cin >> c[i];
 int n;
 std::cin >> n;
 f[0] = 1;
 for (int i = 0; i < 4; i++) {
 for (int j = c[i]; j < 100005; j++) {
 f[j] += f[j - c[i]];
 }
 }
 while (n--) {
 for (int i = 0; i < 4; i++) {
 std::cin >> d[i];
 }
 i64 s;
 std::cin >> s;
 i64 ans = 0;
 for (int i = 0; i < 16; i++) {
 i64 res = 0, cnt = 0;
 for (int j = 0; j < 4; j++) {
 if (i >> j & 1) {
 res += (d[j] + 1) * c[j];
 cnt++;
 }
 }
 if (s - res >= 0) {
 if (cnt & 1) {
 ans -= f[s - res];
 } else {
 ans += f[s - res];
 }
 }
 }
 std::cout << ans << '\n';
 }
} 
int main() {
 std::ios::sync_with_stdio(false);
 std::cin.tie(nullptr);
 go();
 return 0;
}
```

## 复杂度分析

- **预处理**：O(4 × MAX_S)，其中 MAX_S 是最大可能金额
- **每次查询**：O(16 × 4) = O(64)，常数时间
- **总复杂度**：O(4 × MAX_S + 64 × n)

## 关键技巧

1. **避免多重背包陷阱**：使用容斥原理而非多重背包，避免高复杂度
2. **预处理优化**：完全背包预处理可以在所有查询中复用
3. **二进制枚举**：简洁地实现容斥原理
4. **正难则反**：从所有方案中减去不合法方案，比直接计算合法方案更简单
